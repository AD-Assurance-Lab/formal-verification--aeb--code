# First simulator session, 16 August 2026

Ten hours of exclusive simulator access. Kept because the faults found here still cost time
to rediscover. Nothing here changes the design.

**Read this for the faults, not the numbers.** Every measured value below has since been
replaced. The braking limit here is 0.868 g, which a later check found to be an integration
artifact. The real value is about 0.50 g. The map moved twice after this session.

## The simulator will not open a window on this machine

The server exits with code 1 and no output when launched windowed. It starts normally with
rendering off. The cause is that the monitors are switched off, so the display is reachable
but there is nowhere to put a window. It is not a broken install.

Ruled out, so nobody searches again: the display and its authority file, missing libraries,
disk space, and the graphics driver files. All were fine.

Zach normally watches the simulator window, so running with rendering off is a deviation.
Test windowed mode again after any driver or desktop update.

## Five faults that produced confident wrong numbers

The pattern matters more than any one of them. Each gave output that looked reasonable.

| fault | what it reported |
|---|---|
| the car launched down the opposing lane | drove into a junction at 21 m/s, recorded as 4.94 g of braking, verdict PASS |
| speed held by a proportional term only | runs labelled 25 and 50 mph driven at 19 and 38, both exactly 76 percent |
| a swallowed empty-queue error in the capture loop | every image belonged to the previous condition |
| the light given 12 ticks to settle | night endpoints 75 percent too bright |
| a process match that caught the launching shell | server memory reported as a flat 0.00 GB, which reads as no leak |

Four of the five were caught by a result that was physically impossible, not by a test.

## Two faults only a picture showed

The capture ran. The statistics looked fine. The pairing check passed. Then somebody opened
a frame.

**The exposure was six stops too fast.** Daylight sat in the top 40 percent of the range and
the road markings washed out. The clipping check reported 0.1 percent at full white and read
as healthy. A sweep of aperture settled it: f/4.0 uses the full range with no clipping, and
night stays properly dark with the target lit by the headlamps.

**Range meant the wrong thing for the crossing pedestrian.** It was the straight-line gap to
the walker. At a recorded 10.6 m the car was 8.7 m from the crossing point. The walker was
still 6 m off to the side. Obvious in the frame. Invisible in the numbers.

**Look at the data.** Five faults this session came from a number that was impossible. These
two came from a picture that was obviously wrong beside statistics that were not.

## The safety budget was validated by accident

A check between the two lighting endpoints reported them as different. Chasing it:

- One run in ten returned a standoff of 3.32 feet where the others returned 4.99.
- The difference is one control step of travel at 25 mph. The brake trigger is a threshold
  read once per step, so firing on step N or N+1 shifts the whole stop by that much.
- The required standoff is 3.28 feet. The worst observed was 3.32.

So the worst case clears the requirement by four hundredths of a foot. The reason is that
the required range holds a speed-times-step term for exactly this. A tight correct
budget looks like this. It passes, barely, for a stated reason.

## Traps in how the machine is driven

- **`tail` buffers.** Piping a long job through `tail` leaves the output file empty until
  the job ends, so a healthy run looks dead. Do not pipe a job you want to watch.
- **A command-line match catches the launching shell.** Match the process name, which the
  kernel cuts to 15 characters. A tool that silently measures the wrong process is worse
  than no tool.
- **A pattern kill can kill this session's own shell.** Use explicit process numbers.
- **One client at a time in synchronous mode.** A second script asking for the world while a
  job owns the step just times out. It looks exactly like a dead server.

## What was already true then

- The camera route works on the easy case. Placement error was 0.000 m and the image
  difference 0.0065 to 0.0078. The site had no gradient, so this is the easy case.
- Scene lighting takes about 80 steps to settle after a sun change, not a handful. A capture
  12 steps in reads 75 percent too bright.
- The camera defaulted to automatic exposure, which is the fault this lab has published
  about in real datasets, in our own captures.
- The steel plate is tiled to exactly 8.0 by 12.0 feet. The stock prop is a quarter of that.
- The crossing pedestrian is driven by direct control. The built-in walker controller picks
  its own path and would break repeatability.
